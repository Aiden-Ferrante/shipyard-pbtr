# v0.2.0 — Chart core

Light plan (sub-cycle) under [[0.) Development Protocol 1.0]] · super-cycle: [[0.) Road to 1.0]]
Vocabulary: [[7.) Chart Vocabulary]] · opened 2026-08-05

## Problem

Shipyard can show *what* a project is and *whether it moved*, but nothing about **why it exists**.
That reasoning lives in my head and in prose notes, so it never gets checked — the clearest case
being an eight-month-old belief ("I work best on one thing at a time") that July disproved and
nothing flagged. The chart is the object that makes reasoning inspectable.

## Appetite

**One week.** Scope bends, the timebox doesn't. If it slips, cut the composer's optional fields
before cutting the spine.

## Decision required before build

> [!success] Settled 2026-08-05 — **shipyard's sqlite**, with a committed markdown export
> Chose the simple, transactional store over vault markdown. This makes shipyard an **owner of
> truth** — a deliberate exception to "owns no complex logic of its own," and the second one
> alongside `standards.yaml` (which v0.5.0 deletes). Recorded in [[What Shipyard Is (and Isn't)]]
> so the contradiction isn't silent. Needs an ADR.
>
> **Required mitigation — `data/*.sqlite` is gitignored.** The chart is the highest-value artifact
> shipyard will hold, and as things stand it would live in an untracked file with no history and
> no backup. So: **one-way markdown export, committed.** Export only, so no parser and no
> concurrent-edit problem — it buys git history, backup, Obsidian readability, and keeps the
> vault-as-truth option reversible.

## In scope

- One node type: **problem** — title, waypoint, sounding, optional repo, optional anchor
  (`anchored_at` + basis + falsifier).
- **Serves** edges, many-to-many. A problem may have several bearings.
- **Spine view** for one project: bearings above, project centred, children below.
- **Create** with `↑` (why does this matter?) and `↓` (how do I attack it?).
- **Waypoint is a required field.** A problem without one cannot be saved.
- Re-centre by clicking any node.
- The existing board keeps working, untouched.

## Out of scope — pruned

Soundings propagation · drift inbox · thaw cascade · editable groups · heatmaps · deleting the
checklists · write-back to Backlog · drag-to-reparent · fuzzy search. All have their own cycle.

## Guardrails

Inherited from [[0.) Road to 1.0]], plus:

- **No scoring.** The chart describes structure; it never ranks projects.
- **No auto-generated problems.** An LLM guessing your reasoning defeats the purpose.
- **Empty is legible.** A project with no chart shows an invitation, not an error.

## Commit ladder

1. ADR: chart storage — sqlite + committed markdown export — then the schema
2. Problem + edge model, read path, `GET /api/chart/{project}` — tests
3. Spine view renders a hand-seeded chart, read-only
4. `↓` composer — child creation with required waypoint — tests
5. `↑` composer — bearing creation, including attaching to an existing bearing
6. Re-centre navigation + keyboard
7. Markdown export of the chart, written on change and committed
8. Seed Learn Hub's real chart through the UI, not by hand
9. CHANGELOG + tag

## Definition of done

- Learn Hub's chart — 2 bearings, 3 children, 7 grandchildren — created **through the UI**.
- A second project attaches to the shared `<personal goal>` bearing, proving many-to-many.
- Waypoint enforcement verified: saving without one fails.
- The exported markdown is committed and matches what the UI shows.
- `make test` green; `/health` still `ok`.
- Observed output shown, not just "tests pass".

## Retro — 2026-08-05, cut same day

**Definition of done — all met.**

- Learn Hub's chart created **through the UI**: 2 bearings, 3 children, 7 grandchildren.
- `csv-profiler` attached to the shared `<personal goal>` bearing via the picker — that bearing
  now carries 2 projects, proving many-to-many.
- Waypoint enforcement verified in the browser: saving without one returns 422 and the
  composer shows *"a problem needs a waypoint"*.
- `docs/chart.md` committed and matching the UI.
- 22 tests green; `/health` `ok` with all four checks.

**What went right.** The two-questions-as-two-keys framing survived contact — `↑`/`↓` turned
out to be the entire interaction, and the composer needed no other verbs. Making the waypoint a
hard constraint at the API boundary (not a UI hint) meant the rule couldn't be worked around.

**What bit.** The markdown export rendered a two-parent project's *entire subtree twice*, once
under each bearing — the dedup set was per-root instead of shared. Caught only by reading the
generated file, not by any test. The lesson is narrow and reusable: **DAG code needs a
two-parent fixture**, because every tree-shaped test passes happily. A regression test now
exists.

**Appetite.** One week budgeted, finished same day. That's a signal the slice was cut too small
rather than that it went fast — v0.3.0 can take more.

**Carried forward.** Everything is `assumed`; no sounding has been earned. No thaw, no drift
inbox, no editing or re-parenting an existing problem. Cycles are possible in principle.
