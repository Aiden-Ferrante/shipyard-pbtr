# v0.20.0 — The Hub

Sub-cycle 2 of 5 under **The Face**. Opened and closed 2026-08-14 · appetite: one evening.

## Problem

A problem recorded what it is and what would count as progress, but not the approaches
considered, the one chosen, whether it worked, or how far round the loop it had gone. So the loop
ran from memory and got written up in markdown afterwards — exactly what happened to v0.19.0.

## What was done

Five commits: schema + accessors · endpoints · derived Build · the hub view · board rollup.

## The three decisions that carried weight

**A verdict outlives the choice moving on.** Try A, it fails, switch to B, and `A — failed`
remains. Tested at the chart layer and again over HTTP, because deleting that row when the radio
moves is the single worst thing this feature could have done.

**Build is derived and says why.** Read off git as work since the last cut tag. Never stored,
never clickable. And `known` distinguishes "no repo linked" from "not built" — collapsing those
would make *we didn't ask* look like *not done*, which is this cycle's stated failure mode.

**`PhasesIn` forbids extra fields.** Pydantic drops unknown keys, so `{"build": true}` returned
200 with nothing set and a client would have believed Build was ticked. The first test asserted
that 200 and passed. Tightening it to expect 422 is what found the hole.

## What the tests found that reading would not have

- **`ON DELETE CASCADE` had never worked.** SQLite ships with foreign keys off, so deleting a
  problem had been orphaning `problem_edges` rows since the table existed. Found because the
  approaches cascade test failed; entirely pre-existing.
- **The ratchet caught its own author.** The new hub components introduced raw font sizes and
  pushed the count past baseline 43, failing `make check` before commit.

## Retro

Twice the live server served stale code after a restart and I chased a 404 that was only that.
Root cause found and fixed: `__main__` bound `0.0.0.0` while ignoring `SHIPYARD_HOST`, colliding
with `tailscale serve`, so the old process kept the port and the new one exited quietly. Verifying
against a running service needs the restart confirmed — check the route table, not just the health
endpoint.

A browser-automation click on a phase toggle fired no request and I committed step 4 saying the
wiring was unproven. A programmatic `.click()` then set the value correctly. The code was right;
the verification was wrong. Recording it because the commit message still says otherwise and this
is the correction.
