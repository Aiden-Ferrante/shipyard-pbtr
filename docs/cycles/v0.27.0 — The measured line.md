# v0.27.0 — The measured line

Sub-cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-08-16

Addresses **Software Factory**

> Each of standardised intake, named stations, a gate that can stop the line, a cheaper second variant, and a measured line appears in a factory I ran two real projects through — not one I designed on paper.

## Problem

Of the five clauses in the waypoint above, this cycle attacks exactly one: **a measured line.**

Shipyard already has more of a factory than it looks. PBTR is a named station sequence
(`chart.py:1103` `PHASES = ("plan", "test", "review")`, with `build` derived from commits and
never stored — `chart.py:91`); `cycles/open` writes the plan record before anything is cut and
links a version that does not exist yet; the tag closes it, so state is read off disk rather than
typed into. What is missing is not stations. It is that **nothing anywhere records a transition.**

`owed()`, `/activity` and `/cycles` are all *state snapshots* — they answer "what is true now".
A factory claim is about flow, and flow needs two events and the time between them. Concretely:
the `phase_plan` / `phase_test` / `phase_review` columns are bare booleans. `solved_at` and
`active_at` are timestamped; the phases are not. So "how long did this sit at test" is not a hard
question, it is an **unanswerable** one.

What is at stake in getting it wrong is written into the node's own falsifier: *work moves faster,
nothing was cheaper the second time* — a quicker team, not a factory. The only defence against
that reading is a number the line kept itself, and the number has to exist **before** the parts
that are supposed to improve it.

## Appetite

**Deliberately not set here — the duration is the user's to write.** A previous plan in this fleet
carried AI-drafted dates that were later cited back as commitments; the correction was to let
waypoints do the work dates were doing. So this section records the **cut order** instead, which is
the part that actually makes an appetite bind:

1. Cut `rework` first if it runs long. Throughput alone is still a baseline, just a weaker one.
2. Cut the fleet-wide view before the shipyard-only view. One repo's numbers are enough to cut on.
3. **Do not cut the transition timestamps.** They are the only thing here that cannot be
   backfilled — every day without them is a day of flow history that does not exist.

## Plan

**D1 — A new domain module `line.py`, importing nothing from `app`.** The backend is a star, not a
chain (`ARCHITECTURE.md`): no domain module imports another, and `main.py` is the only composer.
*Rejected:* folding this into `repo.py`. `repo.owed()` is deliberately pure over already-computed
values, and walking git history for tag and commit dates is neither pure nor already-computed.

**D2 — Throughput and rework are derived from git. The only thing stored is three timestamps.**
Tags are already dated, in every repo, with no adoption cost — which is the real reason the cycle
won as the unit of flow over the Backlog task, where 4 of the 5 repos checked have zero tasks.
*Rejected:* a `cycle_events` table. Git already holds every event this would duplicate, and a
second home for project truth is what the memory work in v0.26.0 refused on the same grounds.

**D3 — Throughput is never rendered without rework beside it.** Seven of shipyard's twelve tags
were cut on 2026-08-14. A tag is a number you mint yourself, so versions-per-week measured alone is
the vendor-reported speedup trap that this node's own Notes field warns about, self-inflicted.
Rework is the number nobody games in their own favour, and pairing them is what constrains the
reading — the same move as `/api/owed` being grouped and never ranked.

**D4 — No score, and no ranking of repos by line health.** Same call as Owed. A score answers
"which repo is worst"; the question here is "what did this line actually do".

**D5 — Rework is *escaped defect*, windowed, with the head tag excluded.** A defect escaped from
tag T if a fix or revert lands between T and its successor **and** touches code T shipped.
Bookkeeping files — `CHANGELOG.md`, `docs/`, `README.md` — are excluded from the overlap test.
*Rejected:* the definition this plan originally carried, "fix-commits landing after a tag against
files that tag shipped". It was run before being built on, and it failed. See below.

### Measured before building — the definition was refuted, then repaired

Run over shipyard's own history, the original definition failed three ways:

1. **It classified 27 of 27 fix/revert commits as rework.** A measure that flags every fix is not
   discriminating between breaking what was just shipped and repairing something old.
2. **The head tag is a sink.** v0.26.0 scored 8 escapes at rate 1.33 — worst on the board — only
   because every commit after it had nowhere else to land. On a surface, the cycle currently in
   flight would *always* read as the most defective, and worsen until the next tag was cut.
3. **`CHANGELOG.md` and `main.py` are attribution magnets.** Every tag touches them, so overlap
   linked nearly any fix to nearly any tag: `fix(serve): answer HEAD on the root route` was blamed
   on v0.26.0, the *durable memory* cycle, through `main.py`.

Repaired per D5, the last ten closed tags read **126 commits shipped, 11 escaped defects, 5 of 10
cycles leaking at least one.**

It validated against ground truth it was not given: blind file-overlap attributed `e0cc7a8d` to
v0.20.0, and that commit's own message reads *"three v0.20.0 defects found by the sweep"*.
Likewise v0.16.0's three `fix(arguments)` commits trace back to the cycle that shipped
`arguments.py`.

**Still unsolved, and not to be hidden behind a number: the denominator.** `escaped / commits` is
unbounded — v0.18.0 shipped one commit and leaked two, giving "2.00", which is not a rate. Cycles
here range from 1 to 49 commits, so per-commit normalisation is noise at the small end. Ship
instead the **fraction of closed cycles that leaked at all** (5 of 10) beside the raw count (11).
It claims less and cannot produce a nonsense figure.

**Commit ladder.**

1. `phase_plan_at` / `phase_test_at` / `phase_review_at` — nullable, written by the existing
   `set_phases`. Migration in `db()` alongside the v0.24.0 columns.
2. `line.py`: throughput from tag dates, rework per **D5** — escaped defects, windowed to the
   successor tag, magnets excluded, head tag never scored.
3. `GET /api/line`, composed in `main.py`.
4. The surface. Throughput and rework in one component that cannot render one without the other.

**Non-goals.**

- **The gate.** It is v0.28.0, and the separation is the point: a gate added in the same cycle as
  the baseline contaminates the baseline at birth, and nothing afterwards could say what the gate
  changed. Measure first, then give something teeth.
- **Agents, dispatch, and any runner.** The factory is staffed by tools that already exist and
  leave evidence in git; none of that is this cycle.
- **The intake schema**, the station-per-work-item model, and templates carrying scaffolds.
  Three of the five clauses, all later.
- **Anything that scores a project.**

## Exit criteria

The waypoint clause is the honest version: *for work that has gone through, I can state throughput
and rework rate from records the line kept itself — not from memory.*

- [ ] `GET /api/line` reports throughput and rework for shipyard from git alone
- [ ] Three phase timestamps exist and are written on tick; no existing phase behaviour changes
- [ ] The two numbers cannot be read apart — no surface shows throughput on its own
- [x] The rework definition is written down and has been run against real history, including at
      least one cycle where it disagreed with what I remembered — **done before build.** The first
      reading was "v0.26.0 is the worst cycle"; the corrected measure says v0.26.0 cannot be scored
      at all yet, and the worst closed cycle is v0.16.0
- [ ] The head tag is never scored for rework, and the surface says why rather than showing a blank
- [ ] Rework is reported as cycles-that-leaked over closed cycles, never as escapes per commit
- [ ] No new table, no score, no ranking
- [ ] `line.py` imports nothing from `app` — the star holds
- [ ] `make check` clean, tests green, CHANGELOG + tag, `main` fast-forwarded
