# v0.29.1 — No cycle opens on undirected work

Light cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-08-26

Addresses **No cycle opens on undirected work**

> Opening a cycle returns 422 when the repo is uncharted, its problem carries no
> waypoint, or that repo already has a cycle open — each condition planted in a test
> that fails if the check is deleted.

## Problem

Shipyard has exactly one rule with teeth, and it guards the **end** of a cycle:
`_review_gate` refuses to tick `review` while a repo owes uncommitted or unpushed
work — the two debts that mean work would be *destroyed*.

Nothing guards the **start**. `api_open_cycle` checks only that a repo exists beneath
the problem and that an ambiguous one was named. It does not check that the problem
has an observable, or that a cycle is already running in that repo.

That gap already cost something. v0.29.0's changelog says it out loud: the
conventions band and the adoption work *"sat under Unreleased with no tag — an open
cycle by the protocol's own definition"*, and one tag closed both, because no
mechanism could have prevented the second from opening while the first was
unfinished.

What is at stake is whether the chart is upstream of the work or a description
written afterwards. A description nothing consults rots.

## Appetite

One sitting. The refusals and their tests, nothing else.

## Plan

`_open_gate(con, pid, repo)` in `main.py`, directly beside `_review_gate` — composed
there because it needs two domains (the chart names the problem and the repos; git
and the records directory name the state) and no domain module may import another.
Wired into `api_open_cycle` after the repo checks and **before** `scaffold_record`
writes anything.

**Non-goals.** Documentation is not gated here — the standard is being rewritten, and
gating on a definition about to change would bake in the old one. No UI work: the
Yard's gate band claims exactly what the API refuses, so it changes when there is
something new to claim.

## Exit criteria

The refusals exist, each has a test that plants the condition and fails if the check
is deleted, and `make test` and `make check` are green.

## Build

**The prompt asked for three refusals; two of them are reachable.** The gate was
written to refuse (a) a problem with no waypoint, (b) a repo nothing on the chart
claims, and (c) a repo with a cycle already open. Writing (b) revealed it cannot
fire: `chart.nearest_repos()` derives the candidate repos *from chart nodes*, and
`body.repo` is required to be one of them, so a repo the chart does not claim can
never reach this endpoint. The invariant is real and load-bearing; the branch
enforcing it would have been dead code.

Rather than write a branch that cannot execute, (b) became
`test_every_offered_repo_is_charted` — an assertion over `nearest_repos` that the
invariant holds at its source. A refusal nobody can trigger tests nothing; an
assertion on the function that guarantees it tests the actual guarantee.

Per the protocol this is a correction to a fossilised prompt, so it is recorded here
rather than back-edited into §11 of the goal prompt.

**(a) The waypoint refusal is reachable, and not by the obvious route.** A draft
cannot *carry* a repo — `link_repo` already refuses that. But it can **inherit** one:
a waypointless parent whose child carries a repo gets that repo from
`nearest_repos()`, and could open a cycle against an observable it does not have.
That is the case the check catches.

**(c) Scoped per repo, to cycles that compose nothing.** A cycle with problems
beneath it is *supposed* to stay open while theirs run — counting it deadlocks every
child. The discriminator is `chart.children()`, not `chart.role()`, and the planned
list is additionally filtered so a composing cycle's own record does not block the
leaves cutting in the same repo. Both spellings were tried; see Review for why the
first two were wrong. This arc is its own first test — the branch problem stays open
across all three leaves.

Git is read fresh rather than through `_facts_cache`, for the same reason
`_review_gate` documents: a five-second-old answer would refuse a repo you just
closed out, and worse, admit one you just opened.

## Test

`make test` — **438 backend + 5 frontend, green** (430 before this cycle; the merge
of the one-repo-one-problem fix brought three, this cycle brought five).
`make check` clean. The browser suite run separately: 19 passed.

**The negative test, run rather than assumed.** `_open_gate` was neutered with an
early `return` and the suite re-run: three tests failed —
`test_a_draft_problem_cannot_open_a_cycle`,
`test_a_second_cycle_is_refused_while_one_is_open`, and
`test_cutting_the_version_closes_the_cycle_and_the_next_one_opens`. Restored, all
thirteen pass. A gate whose removal breaks nothing has not shipped.

**Not driven in the browser, deliberately.** The cycle's own non-goals say no UI
work, and nothing here is visible from the served app — the refusal is a 422 on a
write route with no surface yet. v0.29.3 changes the Yard and will be driven.

One flake seen and not reproduced: a single `make test` run reported a console 500
from the browser tests, which then passed on two consecutive re-runs and again in
isolation (19/19). Recorded rather than dismissed; if it returns it has a witness.

## Review

**Two corrections to the plan, both found by building it.**

The first is written under Build: the third refusal was unreachable and became an
assertion instead. Worth stating plainly — the plan was wrong in a way that reading
it could not reveal, and only writing the branch showed the branch could not run.

The second was worse, and the tests caught it rather than review. The exemption for
composing cycles was first written as `chart.role(con, pid) != "leaf"`. `role` calls
any parentless node a bearing whether or not anything hangs off it, so that spelling
exempted **every top-level problem**, including a lone one that composes nothing and
is exactly what the gate is for. Keying on `chart.children()` says what was actually
meant.

Then the same deadlock arrived from the other side. Exempting the caller is not
enough: a composing cycle's record lands in the same repo its children cut in, so
opening the branch cycle first blocked every leaf beneath it — `test_a_branch_cycle_
does_not_block_the_leaves_beneath_it` went red on exactly the case D3 was written to
prevent. The fix filters `planned` by whether the problem claiming that version has
children. An **unclaimed** record still contends: nothing on the chart accounts for
it, which is the stray-open-cycle case precisely.

**The plan named the wrong field, and the code says so.** `repo.cycles()` reports
`open` and `planned`, and the goal prompt's own wording — *"a record with no tag is
open"* — is `planned`. `open` is commits since the last tag, which is the normal
state of every repo between releases; gating on it would have refused nearly the
whole fleet on the first try. Caught by reading the return shape before wiring it,
not by a test.

**What carries forward.** D2 and D3 are owed an ADR, per the goal prompt's §8, and
the composing-cycle filter is now the second thing that ADR has to explain. The next
cycle in this arc is `v0.29.2`, the draft queue.
