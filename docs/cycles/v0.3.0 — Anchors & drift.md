# v0.3.0 — Anchors & drift

Light plan (sub-cycle) under [[0.) Development Protocol 1.0]] · super-cycle: [[0.) Road to 1.0]]
Vocabulary: [[7.) Chart Vocabulary]] · opened 2026-08-05

> **Scope revised from the Road note.** It listed v0.3.0 as "soundings that propagate and cap" —
> that shipped inside v0.2.0. What's actually missing is everything that lets a chart be
> *maintained* rather than merely written.

## Problem

The chart is currently **write-once**. There is no way to edit a problem, upgrade a sounding when
evidence finally arrives, record that a belief has been frozen and when, or see what's floating
unattached. A structure you can only add to is a document, and documents rot — that is precisely
how the lane-ladder goal system survived eight months after July disproved it.

Two capabilities close that: **anchors** (a belief frozen on a date, with a basis, thawable when
contradicted) and the **drift inbox** (what serves no bearing).

## Appetite

**Two days.** v0.2.0 budgeted a week and finished in an afternoon, so this slice is deliberately
larger. Scope bends, the timebox doesn't.

## In scope

- **Edit a problem** — title, waypoint, sounding, falsifier. Waypoint stays required.
- **Freeze / thaw an anchor** — `anchored_at` + `anchor_basis` + `falsifier`. Thawing keeps the
  history; it never erases the basis that was recorded.
- **Thaw impact, shown before committing.** What rests on this problem, and critically **which
  descendants survive because they have a second bearing** and which fall to drift.
- **Drift inbox** on the board — problems serving no bearing, with a route to attach or ignore.
- Export gains anchors and thawed state.

## Out of scope — pruned

Re-parenting and detaching edges · deleting problems · cycle prevention · write-back to
Backlog.md · editable board groups · heatmaps · retiring the checklists. Later cycles.

## Guardrails

Inherited from [[0.) Road to 1.0]], plus:

- **No thaw without seeing the blast radius first.** A destructive-feeling action that hides its
  consequences trains you to click through it.
- **Thawing never deletes.** The basis and date stay on the record — the point is a history of
  what you believed and when, not a tidy present.
- **No scoring.** Impact is a count and a list, never a number that ranks anything.

## Commit ladder

1. `PATCH /api/problems/{id}` — edit with waypoint still enforced — tests
2. Freeze / thaw endpoints, history preserved — tests
3. Impact query: descendants, projects, and who survives via a second bearing — tests
4. Edit-in-place on the spine
5. Anchor UI — freeze form, anchored badge, thawed styling
6. Thaw confirm showing impact
7. Drift inbox on the board
8. Export renders anchors + thawed state
9. CHANGELOG + tag

## Definition of done

- A real sounding upgraded on a real problem, and its parent's **effective** grade moves with it.
- An anchor frozen with a basis, visible in `docs/chart.md`.
- Thaw preview run against real data: **Learn Hub survives** a `<personal goal>` bearing thawing
  (it has a second parent), **csv-profiler does not**.
- Drift inbox lists something real.
- `make test` green, `/health` ok, observed output shown rather than "tests pass".

## Retro — 2026-08-05, cut same day

**Definition of done — met, with one honest deviation.**

- Sounding upgraded on a real problem: *Study away from a screen* → `proxy` (audiobook
  generation was verified live in July; listening end-to-end was not, so `proxy` not `observed`).
- **The parent did NOT move, and that is correct.** `effective = min(declared, best child)`, so
  Quality's own `assumed` binds. Recorded below as the cycle's real finding.
- Anchor frozen with a basis, visible in `docs/chart.md` as `**anchored** 2026-08-05` + Basis line.
- Thaw preview run on real data: **11 problems in question, learn-hub's subtree survives via the
  second bearing, csv-profiler alone falls to drift** — exactly as predicted in the plan.
- Drift inbox lists 3 real uncharted projects.
- 34 tests green, `/health` ok, no console errors.

**The finding.** A strong child cannot lift a weak parent. Evidence for one child supports *that
child's* claim, not the parent's. [[7.) Chart Vocabulary]] said the opposite ("the grade at the
top is computed, not typed") and was corrected — the declaration is a ceiling and the children
are a second ceiling.

**What bit — both found by running on real data, neither by a test.**

1. **Survival was one level deep.** Thawing a bearing reported learn-hub's entire subtree as
   orphaned even though learn-hub survived via its second parent. Survival is transitive.
2. **Bearings were reported as drift.** Every parentless problem counted, so the two top-level
   bearings filled the inbox and made it useless.

Same lesson twice, and it's the one to carry: **the tests were tree-shaped and the data is a
DAG.** v0.2.0's retro said DAG code needs a two-parent fixture; this cycle proved it again with
two more bugs. Both now have regression tests.

**Appetite.** Two days budgeted, finished same day again. Estimation is still running ~4× long.

**Carried forward.** Drift can be seen but not resolved — no attach action from the inbox. No
re-parenting, detaching or deleting. Cycles still possible in principle.
