# v0.30.0 — Directed work

Sub-cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-08-26

Addresses **Work is directed before it starts, and closed when it ends**

> For one full month, every version cut anywhere in the fleet traces to a chart
> problem with a waypoint, and no cycle record sat untagged while the next one opened.

## Problem

Shipyard could refuse a sloppy cycle *closing* and nothing about a sloppy cycle
*starting*. The chart was downstream of the work — a description written afterwards
— and a description nothing consults rots. Three leaves attacked that, and this
cycle is the one that composes them.

## Appetite

Three evenings, one per leaf. Held: three sittings, three tags in a day.

## Plan

The three light cycles beneath this problem, then this tag. Prerequisites, no tag:
branch hygiene, and charting shipyard itself.

## Exit criteria

All three PATCH tags exist, and the arc's own rules hold when applied to the arc.

## Test

**The arc was tested against itself, which is the only test that mattered.**

- `chart.role()` reports `branch` for this problem and `leaf` for all three children,
  so the composition the version numbers claim is the one the tree holds.
- This cycle was opened through `POST /api/problems/{id}/cycles/open` — through the
  gate it built — and was admitted: shipyard owed no open cycle at the time.
- With `v0.30.0` open, the gate correctly does **not** block work beneath it: a
  composing cycle's record is filtered out of `planned`, which is ADR 0005's second
  decision holding on live data rather than on a fixture.

## Review

**The arc found three real defects in its own plan, none of them by reading it.**
The third refusal was unreachable; the field named for "an open cycle" was the wrong
one and would have refused most of the fleet; and the exemption for composing cycles
was written twice before it was right. All three surfaced during Build. A plan is a
hypothesis, and this one was wrong in three places that looked fine on paper.

**The Yard cut was cheap because two row counts made it cheap.** `hill_snapshots`
at 0 and `due` at 0 turned "hide or delete" into a decision with no downside. One
query was worth more than the instinct to preserve.

**`chart.children()` answered three separate questions** across three cycles — which
cycles contend, which drafts queue, which records block. That seam is named in ADR
0005 rather than re-derived a fourth time.

### The finding that outlives this arc

**A leaf beneath the repo node cannot open a cycle at all.** `nearest_repos()`
searches **downward only** — a problem carrying a repo answers for itself, and one
above the project layer inherits from the nearest repo below it. Nothing looks up.
Since `_repo_owner` enforces one repo to one problem, the repo sits on the project
node, and every sub-problem beneath it is offered no repo and is refused with *"no
repo beneath this problem — a cycle cuts a version in a repo, and there is none to
cut."*

Verified on live data, not inferred: opening a cycle against **No cycle opens on
undirected work** — a leaf of this very arc — is refused for exactly that reason.

So the three leaf tags in this arc were cut by hand at the shell and linked
afterwards through `POST /api/problems/{id}/cycles`, which does not check repos.
**That is the arc routing around its own rule on its first run**, and it is close
to word-for-word what this problem's falsifier predicted: *"the rules hold and I
route around them."* The falsifier is not satisfied — the work was directed, every
tag traces to a waypointed problem, and nothing sat untagged while the next opened —
but it was avoided by hand rather than by the mechanism, and that distinction is the
whole point of writing falsifiers down.

The intended workflow — a project has its own problem chart, and its sub-problems
lead into cycles — is therefore **structurally blocked today**. Deliberately not
fixed here: repo inheritance is a design change with real consequences for
`versions_claimed_in`, and smuggling it into a closing cycle is how a tag comes to
mean two things. It goes to `Backlog.md`, which is what that file is for and which
this is the first entry of.

The month of observation the waypoint asks for starts now.
