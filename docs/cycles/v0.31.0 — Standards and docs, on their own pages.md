# v0.31.0 — Standards and docs, on their own pages

Sub-cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-08-26

Addresses **Shipyard explains itself**

> From inside the app, without opening the repo, I can read what shipyard enforces
> and what problem it solves — and someone who has never seen it can say what it is
> for after one page.

## Problem

The app that reports every other repo's missing README had its own only in the repo.

Standards sat collapsed at the very bottom of the Yard, below every band, which is
where a convention goes to be indistinguishable from one that does not exist. And it
contradicted the page it sat on: v0.29.3 gave the Yard the waypoint *"shows the
queue, the gate, and receiving, and nothing else"*, and left the standards band
underneath all three.

There was no page at all for what shipyard is for. The `ARCHITECTURE.md` one-liner —
*one pleasant front end over the tools that already hold the truth* — was reachable
only by opening the repo, which is the thing the app exists to save you from.

## Appetite

One sitting. Two pages over endpoints that already exist.

## Plan

`manual.jsx` with two pages: `StandardsPage` over `/api/conventions`, `DocsPage`
over shipyard's own `documents` — the same list the project card renders, opened
through the same `DocPage` reader. A tab strip at the top of the Yard carrying all
three. `StandardsBand` deleted from the Yard.

**Non-goals.** No new endpoint; both reads exist. No editing — a standard's home is
the repo that enforces it and a document's home is the repo that wrote it, which is
the boundary `doc.jsx` already draws.

## Exit criteria

Standards and the manual are reachable from the Yard in one click and from each
other; the Yard no longer carries the standards band; documents open in the existing
reader. `make test` and `make check` green.

## Build

Nothing here was built so much as **given a door**. `/api/conventions` has answered
*what has teeth* since v0.28.0 and `DocPage` has rendered any repo's markdown with a
table of contents since v0.11.0. Both were reachable only by knowing where to look.

**The tab strip is drawn by all three pages, not just the Yard.** Drawn only by the
Yard it would be a one-way door: you would reach Standards from the Yard and then
have to go back to reach the manual. `PageTabs` is exported from `fleet.jsx` and
imported by `manual.jsx` — one more view→view edge, in a file that already has
`goals → argument, graph` and `project → graph, goals`. ARCHITECTURE.md's known-gap
paragraph says that list is either rule 7 or it is not a rule; this cycle adds to the
list rather than resolving the question.

**`SELF = 'shipyard'` is hardcoded.** The manual is not "a project's docs" — the
project card already does that for any repo — it is *this app's* manual, and
parameterising it would invite a second, worse project page.

**Two things found by driving it, neither reachable from a test:**

- A document opened from the manual came back to the *project card*, because
  `DocPage`'s `onClose` was a fixed `openProject(pid)`. A document now has two
  entrances, so the close is `history.back()` — the same call `ProblemPage` makes
  for the same reason.
- `Importable` returned `null` at zero, so the map's Receiving tile scrolled to an
  element that did not exist. True before this cycle and invisible then: receiving
  was one of five stages. It is now one of three, and a dead tile in a three-stage
  map is the map lying. It renders at zero with *"nothing is waiting to be adopted"*
  — deliberately unlike an empty bay, which stays hidden because it is one of
  several and nothing points at it.

## Review

**The cycle that shipped almost no new logic.** Two reads, a nav, and a deletion.
The finding worth keeping is that both surfaces already existed and had for
twenty-odd versions; what was missing was that neither had a route. Reachability is
a feature and it does not look like one in a diff.

**The Yard's waypoint did the work.** *"Shows the queue, the gate, and receiving, and
nothing else"* is what decided standards should leave rather than be moved up the
page, and it decided it without a discussion. A waypoint written one cycle ago
settled a layout question in the next — which is the whole argument for writing them.

### The blocker, hit again on the first cycle after recording it

`Backlog.md`'s first entry is that a sub-problem beneath a repo node cannot open a
cycle, because `nearest_repos()` searches downward only. This cycle hit it
immediately: **Shipyard explains itself** was created as a leaf, and

```
POST /api/problems/<leaf>/cycles/open
→ 422 "no repo beneath this problem — a cycle cuts a version in a repo,
       and there is none to cut"
```

So the cycle was opened against the **branch** instead, which carries the repo — and
that is why this is a MINOR sub-cycle rather than the PATCH light cycle the work
actually was. **The chart's shape is now choosing the version number**, which is
backwards: `repo._weight()` and `chart.role()` are supposed to agree because the work
has a size, not because only one node can hold a cycle.

Twice now the workaround has been the same, and the second time it distorted the
version. That is enough evidence: repo inheritance should be the next cycle, ahead of
any further feature.
