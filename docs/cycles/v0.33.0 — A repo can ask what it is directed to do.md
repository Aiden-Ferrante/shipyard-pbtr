# v0.33.0 — A repo can ask what it is directed to do

Light cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-09-04

Addresses **A repo can ask what it is directed to do**

> GET /api/direction?repo= answers for all 8 board repos with the active problem, open cycle and what would be refused, and pbtr reads it before Plan.

## Problem

Shipyard's two gates refuse at the API, but an agent only learns what it is directed to do by being refused — after it has planned, edited and tried to open. Nothing answers "what is this repo for right now, and what would be refused if I tried" in one read. So sessions start undirected, the fleet's own builder probed a write tool to discover a gate (cycle A's record), and helm's Focus card shows four empty bearings nobody is told about.

## Appetite

One evening, in a worktree: another session holds shipyard's working tree.

## Plan

`GET /api/direction?repo=` composing the repo's problem, its bearing, the focus occupant, any open cycle, and — from the same functions the write routes raise — what `open` and `review` would refuse, plus one `next` sentence. The gates are split into `_open_gate_reason` / `_review_gate_reason` + raising wrappers so "would be refused" and "was refused" are one computation. The `pbtr` skill gains Phase 0 (ask first; stop on a refusal). The fleet MCP gains `shipyard_direction`.

**Non-goals.** No new gate. No writes. No change to what `open`/`review` refuse. Not the session ledger (B) or tokens (C).

## Exit criteria

Direction answers for every board repo on the live chart; an unknown repo is a 404 naming the ids; a test opens a cycle the endpoint said would be refused and the refusal text matches word for word; `test_gate.py` unchanged and green.

## Build

- Built on branch `agentics` in `.claude/worktrees/agentics` because the dev checkout carries another session's uncommitted `_task_write` removal; merged onto dev when that lands.
- A draft problem is made through the API by blanking a waypoint (`PATCH waypoint: ""`), not by a `draft` field — the create route requires an observable.
- `next` priority: open cycle → no waypoint → no active problem under the bearing → another problem holds the focus → review would be refused → clear. The review debt is reported but does not block opening; that is what the gates already say.
- `learnhub-core` is not a manifest id — the repo is `learn-hub`; the 404 names every id so that is a one-read fix, not a mystery.
