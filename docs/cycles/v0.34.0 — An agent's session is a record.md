# v0.34.0 — An agent's session is a record

Light cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-09-04

Addresses **An agent's session is a record**

> Every Claude Code session that touches a fleet repo appears in GET /api/sessions with its commits, tags, anchors and cycles, with no human typing.

## Problem

No column in any fleet app records who changed what. The user's founding complaint for helm — "no robust system to keep track of my agents when I end sessions" — was answered for decisions (anchors) but not for sessions: what an agent committed, tagged, anchored and opened while the human was away lives in eight git logs and nowhere as one record.

## Appetite

One evening, in the `agentics` worktree.

## Plan

`backend/app/ledger.py`: `sessions` + `session_events` (append-only) + `problems.updated_by`; `X-Actor` → contextvar via middleware; chart write routes record their own events when the actor is a session; `/api/sessions` routes for the hooks (start / end / event / list / get). `fleet/hooks/session.py` posts start, end and git events from Claude Code hooks and writes the session file the fleet MCP reads for its actor header. helm shows sessions beside decisions. ADR 0006 says why a stored table is allowed here.

**Non-goals.** No auth on X-Actor (a record, not identity). No rollups stored. No transcript reading. Not the impact tokens (C).

## Exit criteria

A real session walked through the hooks against a served copy of the chart: the row exists with repo, the commit event carries the real sha, a chart write with `X-Actor: claude-code:<sid>` appears as an event and stamps `updated_by`, the end hook closes the row. helm renders the section.

## Build

- Actor via a contextvar set by middleware, so seven write routes gained one `ledger.record(...)` line each instead of a `Request` parameter.
- `ledger.record` swallows sqlite errors: a ledger failure must never undo a chart write.
- An event before its SessionStart creates the session row bare — hook ordering must not lose an event.
- First run: `NameError: repo` in the cycle_open record (the local is `body.repo`); a helm test file was appended into this worktree by a relative path from the wrong cwd and deleted.
- The dev checkout is still held by another session, so v0.34.0 is tagged on `agentics`; review ticks at merge.
