# v0.36.0 — would_refuse names only the next step

Light cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-09-05

Addresses **A repo can ask what it is directed to do**

> GET /api/direction?repo= answers for all 8 board repos with the active problem, open cycle and what would be refused, and pbtr reads it before Plan.

## Problem

`GET /api/direction` (v0.33.0) returned `would_refuse` as the union of both gates. A repo mid-work
always owes something, so for any repo with uncommitted files the list said "review: owes N
uncommitted" — and `next` said "open is clear; closing would be refused today". The fleet bench
(fleet v0.4.0, pass 1) showed what an agent does with that: told "if it would refuse, stop", the
default model stopped at step 1 three times out of three, before opening a cycle that nothing was
refusing. The field answered a question the caller had not asked.

## Appetite

An hour. Six lines in the endpoint, two tests, one tool description.

## Plan

`would_refuse` names only the next step's gate: no cycle open → the open gate; a cycle open → the
review gate. `gates` keeps both, unchanged. `next` drops the "closing would be refused today"
branch when no cycle is open (that repo is "clear") and appends the review reason to the open-cycle
sentence instead, where it is actually the next thing in the way.

**Non-goals.** No change to either gate. No change to `gates`. The pbtr skill and the guard hook
read `would_refuse` and `next` exactly as before — they just stop less often, and only for cause.

## Exit criteria

1. A repo with owed work and no open cycle: `would_refuse == []`, `next == "clear"`, `gates.review.ok == false` still visible.
2. A repo with an open cycle: `would_refuse` carries only the review reason; `next` names the open cycle and the review reason.
3. Live: `GET :8845/api/direction?repo=shipyard` while this cycle is open shows exactly that.

## Build

- `main.py::api_direction`: `would` built from `open_cycle`; the `elif review_reason` branch of `next` removed; review reason appended to the open-cycle sentence.
- `tests/test_direction.py`: the owed-work test now asserts `[]` and "clear"; a new test opens a cycle (v0.2.0 — the fixture already cut v0.1.0, which cost one red run) and asserts review-only.
- fleet `tools.yaml`: `shipyard_direction`'s description says the field names only the next step's gate (fleet, unreleased).

## Test

`backend/.venv/bin/python -m pytest tests -q` → **461 passed** (`test_direction.py` 8, two of them this cycle's).

Live, :8845 restarted through Mission Control with this cycle open and its files uncommitted (2026-09-05):

```
$ curl ":8845/api/direction?repo=shipyard"
open_cycle:   {version: 0.36.0, record: "v0.36.0 — would_refuse names only the next step.md"}
gates:        open {ok: true}  review {ok: false, reason: "review refused: shipyard owes 4 uncommitted"}
would_refuse: ["review: review refused: shipyard owes 4 uncommitted"]
next:         "cycle v0.36.0 is open on shipyard — cut its tag (and tick review) or abort it …; review would be refused today: review refused: shipyard owes 4 uncommitted"
$ curl ":8845/api/direction?repo=helm"
gates: both ok · would_refuse: [] · next: "no active problem under '<domain>' — …"
```

The no-cycle-but-owed-work case (`would_refuse == []`, `next == "clear"`) is covered by the fixture test; no board repo was in that state at the time of the live check.

## Review

- The bench earned this change: the field was designed by the session that also wrote the gates, so "everything that could refuse" looked like helpfulness. The first agent that was not that session read it as an order.
- Observation, not chased: with this cycle open, live `gates.open.ok` was **true**, while the fixture test asserts an open record refuses a second open. The live problem is a leaf like the fixture's. Something differs between the live records dir and the fixture's — worth its own look before anyone relies on `gates.open` mid-cycle.
- The refusal wording is now doubled ("review: review refused: …") because `_review_gate_reason` already prefixes itself. Cosmetic; left, since the guard hook and pbtr match on the field, not the prefix.
