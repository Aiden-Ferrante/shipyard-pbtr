# v0.36.1 — gates.open answers for the leaf

Light cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-09-05

Addresses **A repo can ask what it is directed to do**

> GET /api/direction?repo= answers for all 8 board repos with the active problem, open cycle and what would be refused, and pbtr reads it before Plan.

## Problem

The v0.36.0 record noted: live `gates.open.ok` was true with a cycle open on shipyard, while the
fixture test asserted an open record refuses a second open. Cause: direction resolves a repo to the
problem that *owns* it — for shipyard that is "Work is directed before it starts…", a branch with
ten children — and `_open_gate_reason` exempts any problem with children (a composing cycle is meant
to stay open while its leaves run). The fixture's owning problem was a leaf, so it refused. Live,
every board repo's owning problem composes, so `gates.open` could never say no — while the leaf an
agent actually opens on would be refused by the in-flight check one line further down.

## Appetite

An hour. One keyword argument, one call site, one test.

## Plan

`_open_gate_reason(con, pid, repo, *, as_leaf=False)`: when `as_leaf`, skip the composition
exemption and run the in-flight check regardless. Direction passes `as_leaf=True`, because the
question it exists to answer is "what will the cycle I am about to open be told", and a cycle is
opened on a leaf. The gate's own behaviour on the open route is untouched.

**Non-goals.** No change to which problem direction resolves. No new field.

## Exit criteria

1. Fixture: owning problem with a child whose cycle is open → `gates.open.ok == false` with the in-flight reason; the owning problem can still open its umbrella cycle.
2. Live, with this cycle (v0.36.1, on a leaf) open: `GET :8845/api/direction?repo=shipyard` shows `gates.open.ok == false`.
3. Repos with nothing in flight still read `ok`.

## Build

- `main.py`: the keyword argument and its comment; direction's call site.
- `test_direction.py`: the new test; both cycle-opening tests now `unlink` the record file on cleanup — the first run of the new test was refused by the previous test's leftover record ("dir-beta already has a cycle open (v0.2.0)"), which is the gate working and the fixture lying.

## Review

- The v0.36.0 observation was a real defect and a cheap one: direction was asking the gate a question about the wrong node. Every board repo's owning problem composes, so the field had been constant-true in production since v0.33.0 and nobody could have noticed from the UI — only from a fixture that happened to use a leaf.
- The fixture bit back once more: an unlinked cycle leaves its record file, and "planned" is the file. That is the gate being right about a test that cleaned up wrong. Worth remembering when the next test opens a cycle.
- mission-control reads "uncharted" because it has no chart problem. Not a defect; a fact the read now states plainly.
