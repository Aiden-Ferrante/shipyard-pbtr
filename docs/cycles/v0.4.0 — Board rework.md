# v0.4.0 — Board rework

Light plan (sub-cycle) under [[0.) Development Protocol 1.0]] · super-cycle: [[0.) Road to 1.0]]
Opened 2026-08-05

## Problem

The board still looks the way it did before any of this started. Its three sections —
`spike / tool / product` — are hardcoded in `App.jsx` and come from a fixed vocabulary in
`standards.yaml`, so they can't be created, renamed, deleted, or reordered. And a project card
shows a single "16d ago" stamp where what's actually wanted is the shape of the work over time.

Both were the original asks: **fully user-editable lanes with drag-and-drop**, and a
**per-project GitHub-style activity heatmap** (per project, not fleet-wide).

## Appetite

**One day.** Previous two cycles ran ~4× under their estimate; this one is sized accordingly
rather than optimistically.

## Decision — where groups live

> [!important] Not sqlite. The rule from [[What Shipyard Is (and Isn't)]] holds.
> A third "shipyard owns truth" exception would mean the definition is wrong. So it splits:
>
> - **Membership → the project's own `PROJECT.yaml`.** Which group a project is in is a fact
>   about that project and belongs with it. Shipyard writing that field is the **first real
>   write-back**, pulled forward from v0.6.0 — and it is what makes "reads *and writes* the
>   tools that hold the truth" true rather than aspirational.
> - **Definitions and order → a committed `groups.yaml`** in shipyard. A config file, versioned,
>   hand-editable. Not a database.
>
> **Guardrail on the write:** `PROJECT.yaml` files carry hand-written comments. A
> `yaml.safe_dump` round-trip would silently delete them. The write must be a **surgical line
> edit** that touches only the one field, with a test proving comments survive.

`stage` stays the field name — it is already the contract, already in every manifest, and
renaming it would be churn for no gain. What changes is that its values are no longer fixed.

## In scope

- `groups.yaml`: ordered group list with id, name, colour. Defaults seeded from today's
  spike/tool/product so nothing breaks on upgrade.
- Create / rename / delete / reorder a group.
- Drag a project card between groups; the change lands in its `PROJECT.yaml`.
- Board renders groups from config, not from a hardcoded array.
- Per-project activity heatmap from real commit history.

## Out of scope — pruned

Retiring the checklists (v0.5.0) · the nested-work dashboard (v0.5.0) · write-back to
Backlog.md (v0.6.0) · drag *problems* in the chart · group-level metrics or scoring.

## Guardrails

- **Never rewrite a file we didn't author more than we must.** One field, one line, comments
  and key order intact.
- **Deleting a group must not orphan projects.** Reassign or refuse; never silently drop.
- **A repo that can't be written is a visible failure, not a silent no-op.**
- No scoring, no ranking of groups.

## Commit ladder

1. `groups.yaml` + loader, defaults seeded — tests
2. Surgical `stage:` write-back into `PROJECT.yaml`, comment-preserving — tests
3. Group CRUD API + project-move API — tests
4. Board renders from config
5. Drag-and-drop between groups
6. Group create / rename / delete UI
7. Activity endpoint: per-day commit counts — tests
8. Heatmap on the project card
9. CHANGELOG + tag

## Definition of done

- A group created, renamed, and deleted through the UI.
- A project dragged to another group, and `PROJECT.yaml` on disk shows the change **with its
  comments intact** — verified by reading the file, not by trusting the API.
- Heatmap shows real commit history, and a quiet project looks visibly quiet.
- `make test` green, `/health` ok, observed output shown.

## Retro — 2026-08-05, cut same day

**Definition of done — all met.**

- Group created (`Season`), renamed (`Side Quests`), deleted — all through the UI. Deleting a
  group holding projects was refused by name, as designed.
- `csv-profiler` dragged spike → tool and **shipyard dragged tool → product**, then both
  restored. `git diff` on shipyard's own manifest showed **exactly one changed line**, with the
  header comment, `mc: [shipyard]` flow style and key order all intact.
- Heatmap shows 182 cells / 14 lit for Learn Hub — matching the 14 commit-days in `git log`.
- 52 tests green, `/health` ok.

**The decision that mattered.** Editable groups needed a home, and sqlite was the obvious one —
which would have been the third "shipyard owns truth" exception. The rule written in v0.2.0
("if a third is proposed, the definition is wrong") did its job: it forced the split into
membership-in-the-manifest and definitions-in-config, and that turned out to be *better*, not
just more principled. It made the first real write-back happen a cycle early, which is the thing
that makes the product's own one-liner true.

**What I was most worried about, and why it didn't bite.** Writing into repos shipyard doesn't
own is genuinely dangerous — `yaml.safe_dump` would have quietly eaten every comment in every
manifest. Choosing a regex line-edit over a round-trip, and testing comment survival *before*
building any UI, meant the risky part was settled while it was still cheap.

**No new bugs this cycle** — the first time that's true. Plausibly because the DAG lesson from
v0.2.0/v0.3.0 finally landed: the write-back tests were written against a manifest that had
comments, a trailing comment, and flow-style lists, rather than a clean one.

**Appetite.** One day budgeted, finished same day. First estimate that wasn't wildly long.

**Carried forward.** Group reorder has an API but no UI. New groups are always blue. The heatmap
is in the panel, not on the card.
