# v0.7.0 — The chart is the board

Light plan (sub-cycle) under [[0.) Development Protocol 1.0]] · super-cycle: [[0.) Road to 1.0]]
Opened 2026-08-06

## Problem

The app is currently backwards. **Projects are the primary object and the chart is bolted onto
them** — you start from a repo and optionally record why it exists. That is not how the work
actually goes: the reasoning comes first, and a project is what you create once a subproblem is
concrete enough to attack.

So the model inverts. **The chart is the product. A project is a problem you have decided to
attack** — a problem with a repo attached. Everything else follows from that.

## Appetite

**One day.**

## Decisions (taken 2026-08-06)

- **Board sections are root problems** — every parentless problem is a section, in creation
  order. *Self-organising consequence:* add a parent above two sections and they stop being
  roots, merging into one. The board always shows the highest level currently being organised by.
- **Organise by purpose; maturity survives as a field.** `spike / tool / product` stops being the
  grouping key and becomes a chip on the card, read from `PROJECT.yaml` `stage:`.
- **Promote = link an existing repo.** Attaching a `PROJECT.yaml`-carrying repo to a problem.
  Shipyard does not scaffold new repos — that is a different product.
- **Ghost cards.** A problem with no repo shows as a card in a distinct, unfilled style. The gap
  between *decomposed* and *being worked on* is exactly what should be visible.
- **Dragging re-parents on the chart.** It changes what the work is *for*, which is a far more
  meaningful action than moving it between lifecycle buckets.
- **Nothing disappears.** Projects with no problem node get an `Uncharted` section at the bottom
  — the on-ramp to charting them, not a silent omission.

## In scope

- Board renders from the chart: roots as sections, projects + ghosts beneath.
- Maturity chip on cards.
- Promote a problem to a project (repo picker over unlinked manifests).
- Re-parent by drag (`PUT /api/problems/{id}/parent`).
- `Uncharted` section.
- **Retire `groups.yaml`** and the group CRUD API.

## Out of scope — pruned

Creating repos · multi-parent display (a card shows once, under its first bearing) · reordering
sections · per-section colour · promoting a problem into a *new* repo · the drift inbox's attach
action.

## Guardrails

- **Nothing vanishes from the board.** Every manifest is visible somewhere, always.
- **Re-parenting never orphans.** Replace the edge; never remove without adding.
- **A ghost is visibly not a project** — no fake status, no fake activity.
- Deleting `groups.yaml` must not touch `PROJECT.yaml` `stage:` values; they become maturity
  in place.

## Commit ladder

1. `set_parent` (replace edge) + `unlink`/`link` repo on a problem — tests
2. `GET /api/board` — roots, their subtree projects, ghosts, and the uncharted list
3. Board renders from it; maturity chip
4. Promote control with a repo picker
5. Drag to re-parent
6. Retire `groups.yaml` + group routes
7. CHANGELOG + tag

## Definition of done

- The board shows **two sections** (the current two bearings), Learn Hub and csv-profiler under
  them, ghosts for the undecomposed problems, and an `Uncharted` section holding First Contact,
  GLM Harness and Shipyard.
- A ghost promoted to a project by linking a real repo, verified on disk.
- A card dragged between sections, and the chart's edges reflect it.
- `groups.yaml` gone; no `PROJECT.yaml` `stage:` value changed by its removal.
- `make test` green, observed output shown.
