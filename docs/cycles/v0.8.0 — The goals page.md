# v0.8.0 — The goals page

Light plan (sub-cycle) under [[0.) Development Protocol 1.0]] · super-cycle: [[0.) Road to 1.0]]
Opened 2026-08-06 · Direction **A** chosen from three mocks

## Problem

There is nowhere to **author** the goal structure. The chart exists, but it is project-scoped and
composer-driven: one dialog per problem, reached by first opening a project. That is fine for
adding a rung while thinking about one thing, and hopeless for the actual job — sitting down and
decomposing *"<personal goal>"* into five subproblems in one pass.

The board now shows goals. Nothing lets you build them.

## Appetite

**One day.**

## The shape — outline plus rail

An indented, collapsible outline of the whole chart on the left; a detail rail on the right for
the selected problem. Chosen over Finder columns (navigates well, cannot be authored — "add a
goal above this one" has no natural gesture) and over the spine-as-page.

> **The spine collapses into this.** C's centre card and A's rail carry identical information,
> so building A yields C for free. The existing project-page chart tab becomes the read-only
> view it was always better suited to being.

## Decision — drafts, because the waypoint rule fights typing speed

> [!important] A row created in the outline may have no waypoint yet. It is a **draft**.
> The rule since v0.2.0 is that a problem without an observable is a category, not a problem —
> and the API enforces it with a 422. That rule is right, and it is also fatal to an outline:
> you cannot demand a waypoint between `Enter` and the next thought.
>
> So creation in the outline is allowed to leave it blank, and the row is marked a **draft**:
> visibly flagged, **cannot be linked to a repo**, and does not contribute a sounding. The rail's
> waypoint field is auto-focused so the honest path is the fast one.
>
> The spirit survives — *no unfalsifiable problem becomes real work* — while capture stays quick.
> Drafts are debt, and the page should say how much of it there is.

## In scope

- **`#/goals`** page with a nav link.
- Outline of every root and its descendants, collapsible, with **duplicate handling**: a problem
  with two bearings renders expandable at its first occurrence and as a *shown above* reference
  at the second. Never two editable copies.
- **Keyboard authoring** — `Enter` new sibling, `Tab` indent (re-parent under previous sibling),
  `Shift-Tab` outdent, typing edits the title inline, `↑`/`↓` move selection.
- **Detail rail** — waypoint, sounding, falsifier, rejected alternatives, anchor basis, what
  rests on this, also-serves, and the freeze / link-repo actions.
- **Undo for structural moves.** `Tab` silently re-parents a chart edge; that needs to be
  reversible or it will be done by accident and not noticed.
- Draft count surfaced somewhere honest.

## Out of scope — pruned

Sibling ordering / drag-to-reorder · multi-select · search within the outline · persisting
collapse state across reloads · editing waypoints inline in the outline (rail only) · deleting
problems · merging duplicates.

## Guardrails

- **A structural change must be visible and reversible.** No silent re-parent.
- **Never two editable copies of one problem.** The reference row is inert.
- **A draft cannot become a project.** Linking a repo requires a waypoint.
- The outline is the *only* place structure can be edited by keyboard; the rail edits content,
  never shape.

## Commit ladder

1. Drafts: allow blank waypoint at creation, derive `draft`, refuse repo-link — tests
2. `GET /api/goals` — the whole chart as an ordered outline with reference marking — tests
3. Outline renders, collapsible, read-only
4. Keyboard authoring against the existing create / re-parent endpoints
5. Detail rail
6. Undo stack for structural moves
7. `#/goals` route + nav
8. CHANGELOG + tag

## Definition of done

- A three-level goal tree built **from empty, keyboard only, in under a minute** — recorded as a
  step count, not a feeling.
- `Tab` re-parents; undo puts it back, verified against `GET /api/chart`.
- A two-parent problem appears once expandable and once as a reference.
- A draft is visibly flagged and refuses a repo link.
- `make test` green, observed output shown.
