# v0.9.0 — Arguments

Light plan (sub-cycle) under [[0.) Development Protocol 1.0]] · super-cycle: [[0.) Road to 1.0]]
Opened 2026-08-06

## Problem

A waypoint is asserted, not argued. You pick a sounding from three chips and nothing anywhere
says *why* that grade is deserved. The chart records structure and evidence *labels*; it records
no reasoning.

The intent: **every waypoint is the thesis of a short argumentative essay with evidence.** The
sounding should be the conclusion of that argument rather than a chip you clicked.

## Appetite

**One day.**

## Decisions

- **Arguments are plain markdown files. Nothing Obsidian-specific.** Shipyard scaffolds, reads
  and writes them; any editor can open the same file.
- **They live in the repo** — `docs/arguments/`, beside `docs/chart.md`. Versioned with the code,
  works on a fresh clone, no external path assumptions. `SHIPYARD_ARGUMENTS_DIR` moves them
  (a vault, say) without touching anything else.
- **Plug-and-play editing via one config line:** `SHIPYARD_EDITOR_URI`, a template like
  `obsidian://open?vault=Obsidian&file={path}` or `vscode://file/{abspath}`. Your editor is the
  *better* experience, never the *required* one — shipyard can always edit inline, so the app is
  not broken for anyone who hasn't configured it.
- **A short `reasoning` field on the problem**, separate from the essay: one or two sentences,
  the compressed why, visible in the rail without opening anything.
- **Writes are mtime-guarded.** If the file changed on disk since shipyard loaded it, the write
  is refused rather than clobbering prose written elsewhere.

## The verdict question

The essay ends in a **Verdict** line — `assumed | proxy | observed`. Tempting to make it the
single source of the sounding and turn the chips read-only.

**Not yet.** v1 **parses the verdict and shows a mismatch** — *"the argument says observed, the
chart says assumed"* — with a one-click reconcile. A nudge, not an automatic write: silently
changing a grade because prose changed is exactly the kind of invisible mutation this app exists
to prevent. If the nudge proves reliable, tightening it later is easy; the reverse is not.

## In scope

- `reasoning` column (migrated onto existing DBs) + rail field.
- `arguments.py` — path resolution, scaffold, read, mtime-guarded write, verdict parse.
- `GET`/`PUT /api/problems/{id}/argument`, `POST` to scaffold.
- Rail: reasoning, argument preview, edit inline, *open in your editor* when configured.
- Verdict-vs-sounding mismatch indicator with reconcile.

## Out of scope — pruned

Rendering markdown to HTML (plain textarea is fine) · evidence as structured rows · citation
checking · syncing the thesis line when a waypoint changes (shown as a mismatch instead) ·
templates per problem type · full-text search across arguments.

## Guardrails

- **Never overwrite prose shipyard did not write.** mtime guard, and scaffolds are create-only.
- **No automatic sounding changes.** Mismatch is surfaced; the human reconciles.
- **The app works with no editor configured.** External editing is an enhancement.
- A missing or deleted argument file is a normal state, not an error.

## Commit ladder

1. `reasoning` column + migration + PATCH — tests
2. `arguments.py`: scaffold / read / guarded write / verdict parse — tests
3. API endpoints
4. Rail: reasoning + argument panel
5. Mismatch indicator + reconcile
6. CHANGELOG + tag

## Definition of done

- An argument scaffolded from the rail for a real problem, thesis pre-filled from the waypoint,
  file present in `docs/arguments/` and committed.
- Edited inline, saved, and the change visible on disk.
- A write refused after the file is changed underneath shipyard.
- A verdict of `observed` against a chart sounding of `assumed` shows the mismatch and reconciles
  in one click.
- `make test` green, observed output shown.
